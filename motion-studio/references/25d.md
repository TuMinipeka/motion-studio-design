# Producción 2.5D con referencias, recursos y un reloj común

Si el trabajo se reparte entre subagentes de Claude Code, aplica [paralelo.md](paralelo.md): un escritor por archivo, generadores por plano cuando convenga, dependencias fijas durante cada render y cola de GPU del coordinador. El reparto complementa este flujo y conserva sus autorizaciones.

Lee esta guía para un corto de personajes gráficos dentro de un espacio 3D, o para componer secuencias prerenderizadas. Es el modo animación de Motion Studio: Blender genera recursos opcionales; `window.seek(t)` compone, `render.mjs` exporta y las revisiones habituales siguen vigentes. No requiere instalar otra skill. Las autorizaciones del brief, GPU, muestra y completo no cambian.

## Referencia que se pueda comprobar

Antes de producir, observa el archivo completo y registra su URL, autor declarado y alcance de uso en el brief. Con una copia local:

```bash
python <skill>/scripts/referencia.py referencia.mp4 --url https://fuente-original --salida review/referencias
```

Deja una carpeta por SHA-256 con FFprobe, tamaño/fps/duración, valores `YAVG`, `SATAVG`, `YLOW` y `YHIGH` de FFmpeg a 1 fps, fotogramas y hojas temporizadas. Se mide antes de reducir las capturas. Lee las hojas: el script no identifica personajes, lugares, gags, licencias ni todos los cortes. Un montaje con barridos/fundidos necesita revisar sus cortes; no conviertas un detector automático en el contrato del proyecto. Las bandas de una muestra a 1 fps tampoco equivalen a medir todos los fotogramas.

Anota en el storyboard qué elementos deben verse, tamaños relativos de cara/objeto, composición, cadencia y captions. Distingue datos medidos, conteo visual e inferencias. Usa la historia que necesite el encargo; la estructura paradoja → intentos → explicación → remate del tutorial es una opción para divulgación, no una fórmula obligatoria. Comprueba datos reales y separa los gags inventados.

## Voz antes de cerrar los tiempos

Si hay voz, mide el archivo real antes de bloquear duración y planos. Reutiliza la grabación aprobada; no generes otra toma de pago para ajustar un tiempo. Para obtener marcas locales, con `faster-whisper` instalado:

```bash
python produccion.py --transcribir audio/voz.wav --idioma es --modelo small
```

Escribe `audio/voz.palabras.json`. El decodificador usa FFmpeg y un array a 16 kHz, evitando una incompatibilidad observada entre faster-whisper y PyAV. ASR estima palabras y tiempos: verifica ambos contra el guion y el audio. Una transcripción no es alineación forzada ni precisión de un fotograma garantizada. El modelo puede descargarse la primera vez; el modo CPU/int8 evita ocupar la GPU de imagen. No se impone esta ruta si ya hay tiempos revisados.

`produccion.py --voz` acepta `segments[].words[]` de Whisper, `lines[].words[]` de make-short y `words[]` normalizado (`word`, `start`, `end`; también `w`). No estima tiempos repartiendo palabras por su longitud.

## Plan ejecutable junto al storyboard

`produccion.json` es opcional. Evita otra cronología escrita a mano cuando hacen falta sincronía y muestras por plano. `STORYBOARD.md` sigue conteniendo dirección y fuentes; el JSON solo contiene datos ejecutables. Sus intervalos son enteros absolutos de la entrega, base cero, fin exclusivo:

```json
{
  "version": 1,
  "planos": [
    {"id": "P01", "inicio": 0, "fin": 90, "muestras": [24, 65],
     "impactos": [{"id": "golpe", "fotograma": 63, "efecto": "impacto", "ganancia": 0.8}]},
    {"id": "P02", "inicio": 90, "fin": 180,
     "impactos": [{"id": "respuesta", "palabra": 12, "desfase": 0, "efecto": "tic"}]}
  ]
}
```

El ejemplo supone 6 s a 30 fps y al menos 13 palabras revisadas. Un impacto usa `fotograma` **o** el índice global `palabra` (base cero), con desfase opcional en segundos. Los fps vienen de `motion.config.json`: no se fija 30 en el cálculo. Un impacto visual confirmado tiene prioridad sobre una marca ASR: escribe su fotograma real. Los efectos disponibles son `tic`, `impacto` o ninguno; no es un catálogo sonoro de la referencia.

```bash
python produccion.py --voz audio/voz.palabras.json
# Sin voz: python produccion.py
python audio/musica.py --sincro sincro.json --voz audio/voz.wav
```

Valida cobertura de toda la pieza, huecos/solapes, identificadores, impactos y voz fuera de duración. Escribe `sincro.json` y SRT de una palabra, con final acotado por siguiente palabra, corte y 0,9 s. El SRT se entrega como pista; no se incrusta solo. Para captions dibujados, usa `crearSincro(datos).subtitulo(t)` y `texto()` de `crearTexto`, adaptando fuente, posición y agrupación al brief. Para actuación, `impacto(id)` devuelve el mismo segundo que usa la mezcla. `--sincro` sustituye `GOLPES` por los impactos del JSON; la cuadrícula musical continúa en `beats.json`.

Una línea de voz no obliga a un corte. Protege preparación, acción, consecuencia y reacción en la ficha, incluida la pose extrema. Alinea cortes y momentos importantes con la cadencia real del recurso: a 12 dibujos/s y 30 fps el siguiente dibujo puede entrar uno o dos fotogramas de entrega después de un tiempo arbitrario.

Con `--sincro`, la mezcla añade normalización de dos pasadas (−14 LUFS, objetivo de pico −1,5 dBTP). Revisa el MP4 codificado: el margen de la mezcla no garantiza el pico tras AAC. El modo musical clásico conserva su comportamiento.

## Recursos de Blender sin otro exportador

Blender es opcional (probado con 5.2.3 LTS/EEVEE/OpenGL en Windows). El generador Python del proyecto construye su escena y expone `seek(t)`: fija transformaciones completas, cámara, expresiones y ruido desde tiempo/identidad. Recibe `MOTION_CONFIG` con dimensiones y cadencia. Declara cualquier dependencia adicional con `--fuente`; no ocultes archivos externos en el generador.

```bash
python <skill>/scripts/recursos25d.py --proyecto . --generador escena.py \
  --blender "C:/Program Files/Blender Foundation/Blender 5.2/blender.exe" \
  --gpu NVIDIA --fps 12 --inicio 0 --fin 72 --comprobar
```

Genera PNG nativos para 6 s a 12 dibujos/s, sin cambiar los 30 fps de entrega. La GPU ya debe estar elegida por el usuario. Se inicializa el contexto gráfico y se exige que el nombre **real** contenga `--gpu`; falla antes de generar si no coincide. La opción verifica OpenGL, no selecciona por sí sola una GPU ni cambia Windows. Otro motor/backend necesita su propia comprobación.

Reutiliza solo PNG válidos de una huella de generador, runner, fuentes declaradas, versión de Blender, dimensiones y cadencia. Guarda primero `.part.png`, verifica tamaño/integridad antes y después y escribe los manifiestos estables `recursos/<generador>-<huella>/recurso.json` y `<generador>.recurso.json`. Los informes de ejecución y las repeticiones diagnósticas van a `review/recursos25d`: comprobar no invalida imagen si los recursos siguen iguales. Cambiar código/entradas crea otra carpeta; conserva los recursos anteriores.

`--inicio`/`--fin` definen el alcance completo del recurso en dibujos, fin exclusivo; no son fotogramas de entrega. Para regenerar solo una parte manteniendo ese alcance, usa, por ejemplo, `--inicio 0 --fin 72 --solo=25,30 --forzar`. Si faltan dibujos fuera de `--solo` para esa huella, se detiene: genera primero el recurso completo. Un cambio global de código no permite suponer que los demás dibujos son válidos; divide generadores por plano cuando quieras aislar sus cambios. `--comprobar` repite primero, medio y último en orden inverso y compara exactamente los canales de PNG con Pillow fuera de Blender; falla si difieren. Tres instantes no prueban todo el generador.

Componer bajo demanda:

```js
// Cargar kit/secuencia.js. El manifiesto m procede de escena.recurso.json.
const sec = crearSecuencia({ruta:m.ruta, cantidad:m.cantidad, fps:m.fps,
                          primero:m.primero, digitos:m.digitos, cache:3});
window.seek = async t => {
  const imagen = await sec.fotograma(t);
  ctx.reset();
  ctx.drawImage(imagen, 0, 0, W, H);
  // Textos y otros elementos propios de este plano.
};
await window.seek(0); window.ready = true;
```

`render.mjs` espera la promesa de `seek`. El índice depende del tiempo, no de la captura anterior. El lector mantiene un máximo de `cache` ImageBitmap y cierra los expulsados; no precarga un episodio entero en RAM. Dibuja inmediatamente tras el `await`; no conserves bitmaps expulsados. Un archivo ausente falla con su ruta. Esto prueba reproducción de recursos, no el determinismo del generador.

`assets/ejemplos/25d/` contiene un generador original sencillo, HTML y plan de **6 s, 1080×1920, 30 fps** para comprobar el recorrido. Copia esos tres archivos sobre un proyecto creado con `nuevo.py`, prepara `produccion.py`, genera recursos, mezcla y exporta una muestra autorizada. Es una prueba de desarrollo, no un personaje universal ni el nivel artístico de Ricks Clips.

## Revisar antes de multiplicar planos

```bash
python produccion.py --capturar
node render.mjs --determinismo --t=0,1.5,2.1,3.333333,5.9
node render.mjs --prueba=0,6
```

Captura inicio, centro, final, impactos y extremos declarados; arma hojas por plano y `review/produccion/revision.json`. Acepta `bandas` opcionales por plano (`YAVG`, `SATAVG`: `[mínimo,máximo]`) cuando las justifique la referencia; avisa de desviaciones, sin corregir color ni aprobar el plano automáticamente. Las muestras deben incluir objeto, cara, manos, recorte y grafismo. Revisa también el video, ritmo, lectura y sonido: las hojas no los sustituyen.

En una producción compleja, una revisión independiente puede descubrir errores del constructor. Si se usa, pide evidencia con plano/tiempo y confirma cada observación a tamaño nativo antes de corregirla. No añadas agentes ni puntuaciones de rutina a una pieza sencilla. Registra problemas y correcciones en `REVISION.md`; no conviertas cada error local en una regla global ni una nota subjetiva en garantía de calidad.

Las exportaciones completas siguen requiriendo la aprobación prevista en `SKILL.md`. Su caché incluye huella de fuentes locales de imagen, configuración, página y perfil; un cambio deja de reutilizar segmentos antiguos. Los archivos de audio se excluyen: la mezcla se vuelve a unir en cada ejecución sin rehacer imagen. Si el dibujo depende del audio, precalcula sus datos temporales en JSON dentro del proyecto. La huella no cubre recursos de red, dependencias compartidas modificadas fuera del proyecto ni enlaces simbólicos. Mantén recursos de imagen y versiones/dependencias dentro del proyecto para una exportación reproducible. Una caché correcta reduce renders repetidos; no demuestra mejor calidad artística.
